1、传统工业界采用 I/O 点数作为 PLC 的分类标准
按 I/O 点数分类，是传统工业领域对 PLC 划分的主流分类标准，兼具实用
性与科学性，且在高校教学中被广泛采用。I/O 点数与控制的设备数量、逻辑复
杂度正相关，是直接反映系统复杂度的参数。
（1）I/O 点数与二进制地址位数与工程习惯有关
256（2⁸）和 1024（2¹⁰）为计算机科学中的常见阈值，便于内存分配与系统
设计。例如，256 点对应 8 位地址总线，1024 点对应 10 位地址总线，符合早期
PLC 硬件设计逻辑。
（2）学术教材均明确 I/O 点数的分类标准
多数学术教材均明确以 I/O 点数作为 PLC 的分类标准。例如，普通高等教
育机械类“十二五”规划系列教材《PLC 及电气控制》（电子工业出版社）指出：
“通常将 PLC 的 I/O 点数在 64～256 点之间的称为小型 PLC、通常将 PLC 的 I/O
点数在 256～1024 点之间的称为中型 PLC、通常将 PLC 的 I/O 点数在 1024 点以
上的称为大型 PLC。”
（3）工业实践中适合使用 I/O 点数作为产品选型依据

2、目前 PLC 行业主要采用中大型与小型的二分法分类体系
（1）产业结构、工业实践、市场研究均采用两分法
在产业结构分类、工业实践分类以及市场研究领域中，基于技术特性和应用
规模的考量，对 PLC 已形成明确的二分法分类体系，即划分为小型 PLC 和中大
型 PLC，而非传统的小型、中型和大型三级分类。
在产业结构分类中，《产业结构调整指导目录》（2019 年版）仅在“鼓励类”
产业的“二十八、信息产业”条目下对可编程逻辑控制器进行了单一分类；而最
新生效的《产业结构调整指导目录》（2024 年版）除了保留这一产业分类，更在
“鼓励类”产业的“四十七、智能制造”条目下新增了中大型可编程逻辑控制器
的专门分类，将中型与大型 PLC 合并为同一产业分类。
在工业实践分类中，因中大型 PLC 和小型 PLC 客户类型、应用场景、市场
策略等差异，PLC 厂商通常会分独立事业部或独立产品线，分别对中大型 PLC
和小型 PLC 进行管理，如西门子已将其 PLC 产品系列，从早期的 S7-200 小型
PLC、S7-300 中型 PLC、S7-400 大型 PLC 三大系列，调整为 S7-1200 小型 PLC、
S7-1500 中大型 PLC 两大系列。
在市场研究领域中，MIR 睿工业、华经产业研究院等市场研究机构均采用
中大型 PLC、小型 PLC 的二分法分类标准，并以该分类口径在市场报告中进行
市场规模统计、竞争格局分析等研究工作。

这类应用场景往往具有以下特征：首先，控制对象在地理上呈现分布式布局，
需要多个 I/O 站点的协同工作，要求 PLC 具备远程分布式扩展的能力，因此需
要具备模块背板总线架构设计；其次，系统需要集成多种信号类型，对 I/O 模块
的种类、数量具有一定的要求；最后，系统不仅要求实时数据采集与控制，还要
求结合数据情况，根据复杂控制算法做出控制决策，要求 PLC 具备较好的处理
性能。
因此，面对这类应用场景，并不能通过简单叠加小型 PLC 的数量来实现中

（二）各类型 PLC 产品在工业自动化系统中的功能、技术难度和价值量占
比，其他工业自动化设备与 PLC 产品的适配情况
1、小型 PLC 的功能、技术难度和价值量占比
小型 PLC 控制的 I/O 点数较少，主要用于直接连接伺服系统、电机等驱动
执行设备，满足单机设备控制等 I/O 需求较小的场景，属于“设备级”产品。小
型 PLC 具备紧凑的硬件结构、经济的使用成本和简化的编程环境，广泛应用于
各种制造业的单机设备控制。以典型的包装机械为例，一台小型 PLC 可通过运
动控制功能完整实现薄膜拉伸、成型、充填、封口等工序的时序控制，通过数字
量输入模块采集光电传感器和接近开关信号。
小型 PLC 由于 I/O 点数有限且应用场景相对简单，其技术难点主要集中在

紧凑型硬件设计、基础逻辑控制的高效执行和成本优化方面。一方面，小型 PLC
需要在有限的机身空间内集成电路板、处理器、存储单元和基本 I/O 接口，同时
确保基本可靠性指标，对产品的结构设计具有一定的要求；另一方面，小型 PLC
需要在资源相对受限的硬件平台上实现执行周期确定的控制逻辑，因此需要对软
硬件资源进行裁剪，通过适当精简不需要使用的指令集和优化固件来最大程度利
用有限的资源，保证基础控制功能的实时响应。通常，在一台自动化设备中，PLC
金额占整机成本金额的 5%-15%。
2、中大型 PLC 的功能、技术难度和价值量占比
（1）中大型 PLC 的整体功能、技术难度和价值量占比
中大型 PLC 通过模块化互连构建远程分布式扩展控制系统，适用于控制设
备数量多、空间分布广、控制逻辑复杂的大型工业系统或生产过程，属于“系统
级”产品。中大型 PLC 的研发重点在于核心软件架构、硬件深度开发、通信兼
容适配以及冗余安全等进阶功能实现等维度。在核心软件架构方面，需构建支持
多语言、多任务实时调度及复杂逻辑处理的 IDE，确保 Runtime 的微秒级响应与
高效资源管理；在硬件深度开发方面，需面对多核架构、大规模 I/O 及高可靠性
需求，需优化硬件平台设计，适配主流与国产处理器并解决生态配套问题；在通
信兼容适配方面，需实现多协议集成与复杂网络架构下的高效数据同步，兼顾跨
厂商设备互联与通信安全性；在冗余安全进阶功能方面，需通过毫秒级热备切换
与多级冗余机制保障系统高可用性，平衡同步精度与性能损耗。通常，中大型
PLC 投入金额占整个系统的成本投入比例约为 10%-15%左右。
（2）中型 PLC 与大型 PLC 的技术特性、市场应用领域对比
整体而言，中型 PLC 的系统架构、扩展能力、通信能力等技术特征与大型
PLC 一致。中型 PLC 与大型 PLC 在技术特性方面的异同具体表现为以下五个维
度：
1）系统架构方面，中型 PLC 与大型 PLC 设计理念一致
中型 PLC 与大型 PLC 均采用模块化架构设计，支持包括 CPU 模块、I/O 模
块和通信功能模块在内的灵活配置，小型 PLC 主要采用整体式架构设计，并根
据需要扩展有限的外围模块。在系统架构复杂度上中型PLC显著高于小型PLC，

与大型 PLC 一致。这种架构设计使得中型 PLC 具有一定的系统扩展性，技术难
度也高于扩展能力有限的小型 PLC。根据公司报告期内各类模块销售情况来看，
中型与大型 PLC 在产品模块结构、数量关系方面均基本一致，具体如下：

2）扩展能力方面，中型 PLC 与大型 PLC 一致
中型 PLC 的标准 I/O 处理能力覆盖 256-1024 点范围，并可以通过远程 I/O
模块的形式进行分布式扩展。中型 PLC 的分布式扩展这一特性与大型 PLC 一致，
也使得中型 PLC 相较于小型 PLC 具有更强的带点能力，可以应用于控制规模更
大的自动化系统。
3）通信能力方面，中型 PLC 与大型 PLC 一致

现代中型 PLC 通常支持 PROFINET、EtherCAT、Modbus-TCP 等主流工业以
太网协议，以及 PROFIBUS 等现场总线协议。在通信能力方面中型 PLC 与大型
PLC 一致，显著优于通常仅支持 Modbus RTU 等简单协议的小型 PLC。
4）可靠性能力方面，中型 PLC 通常会弱于大型 PLC
中型 PLC 通常不支持热备冗余等可靠性功能，而大型 PLC 通常均支持热备
冗余功能。基于前述原因，中型 PLC 较少应用于石油石化、轨道交通、水利水
电、船舶等对 PLC 有冗余能力要求且电磁兼容性等环境复杂的项目型市场，该
类市场以大型 PLC 为主。
基于以上技术特点，中型 PLC 在技术层面与大型 PLC 具有同源性，特别是
在系统架构、扩展能力、通信能力方面的特性与大型 PLC 高度趋同，因此可以
胜任中大型规模的自动化系统的控制任务，在行业内也通常将二者的下游市场统
称为中大型 PLC 市场。
相较于大型 PLC 而言，中型 PLC 的可靠性能力有限、不支持热备冗余的特
点使其无法在对 PLC 可靠性要求较高的项目型市场得到大规模应用。
3、其他工业自动化设备与 PLC 产品的适配情况
小型 PLC 主要适配伺服系统、变频器和电机等标准化工业自动化设备，这
类设备通常只需要支持 Modbus、EtherCAT 等几种固定且通用的通信协议即可无
缝通信，小型 PLC 产品与其他工业自动化设备适配的壁垒相对较低。因此，小
型 PLC 具有天然的集成特性，适合在包装机械、小型输送线等标准化程度高的
自动化场景中与其他工业自动化设备形成固定的组合产品。
中大型 PLC 需要适配的设备更为专业和复杂，涵盖大型工业与高端制造业
中的关键设备，如调节阀、流量计、压力变送器等过程仪表，以及中高压变频器、
特种电机、气动执行器等执行机构。中大型 PLC 适配的工业自动化设备通常要
求支持 PROFIBUS、EtherCAT、PROFINET 等多种工业总线协议，部分场景还需
集成 HART、IEC 104 等个别应用领域专用的现场总线，甚至需要通过 MQTT、
OPC UA 等跨平台通信协议与上层系统软件进行数据交互。由于设备种类繁多、
协议复杂，中大型 PLC 在与其他工业自动化设备的适配方面具有一定难度，需
要通过支持更多种类的通信接口以及更丰富的通信协议的方式实现对其他设备

的兼容性和适配性。
（三）PLC 产品的使用寿命、下游客户更新迭代频率或采购周期，是否存
在替代性产品
1、PLC 产品具有较长使用寿命，下游客户对 PLC 具有稳定的采购需求
PLC 作为一种工业设备，在使用寿命上与计算机、手机等消费级产品有明显
的区别，PLC 产品的设计使用寿命通常是在 10 至 15 年，这也是工业自动控制产
品服务于工业现场的稳定性、长期可维护性的需求而产生的特点。
PLC 产品的下游客户主要包括系统集成商和终端用户，二者的采购需求共同
构成了 PLC 市场的稳定需求基础。
系统集成商作为工业自动化系统解决方案的提供者，需采购 PLC 及其他工
控设备，并整合为完整的控制系统交付终端用户。由于其业务模式依赖持续的项
目承接，系统集成商需根据客户需求不断采购 PLC 产品，因此其对 PLC 产品具
有稳定的采购需求。
终端用户作为工控系统的最终使用者，出于系统稳定性的考虑，通常不会频
繁更换已投运的 PLC 设备，其采购周期主要受系统升级周期、备品备件采购需
求等因素影响。具体而言，为确保控制系统长期可靠运行，终端用户通常会在
PLC 投运后 7 至 10 年进行整体更新，以降低因设备老化导致的故障风险。
综上所述，PLC 产品具有较长使用寿命，但由于系统集成商的项目驱动型采
购、终端用户的日常系统维护及迭代更新需求，下游客户对 PLC 的采购需求保
持稳定，支持 PLC 市场的可持续增长。

（1）控制器可分为通用控制器和专用控制器
在控制器产品中，可分为通用控制器和专用控制器，其中 PLC 具备可编程
功能，是最常见的通用控制器；专用控制器（如单片机、PC-based）是针对特定

控制能力、成熟的工业生态体系、较长的生命周期保障、持续的技术演进能力等
特性，是专用控制器难以企及的。专用控制器在部分场景中可以作为 PLC 产品
的补充方案，但并不是 PLC 的完全替代方案，尤其是在高可靠性、高安全性和
强实时性要求的工业场景中，PLC 凭借大量工业现场验证的技术沉淀、完整的国
际标准认证体系、覆盖研发、生产、服务的全产业链生态系统等优势，始终是工

与此同时，不少传统使用专用控制器的领域正在逐渐被 PLC 渗透，在风电
控制系统、楼宇自动化等多个传统由专用控制器主导的领域，已有大量市场份额
被通用 PLC 替代。从技术本质而言，专用控制器实质上是 PLC 的核心技术在部
分场景和个别行业的定制化衍生产品。相比而言，PLC 凭借其标准化架构、开放
生态和可扩展性，依然是工业自动化领域的核心基础设备，尤其适用于需要技术
迭代和系统集成的复杂场景。

（2）PLC 产品具有通用性、易用性、实时性、可靠性等技术优势，技术成
熟度高，在工业控制领域占据核心主导地位
PLC 作为工业自动化控制的核心设备，具有通用性、易用性、实时性、可靠
性等技术优势，在工业控制领域长期占据主导地位。
通用性方面，PLC 作为典型的通用型控制器，在硬件配置、软件功能上不针
对具体行业定制化开发，而是将具体控制逻辑的开发权交给用户，通过编写用户
程序、更改硬件模块配置，PLC 可以用于不同行业的控制系统，不论是简单的逻
辑控制还是复杂的流程控制，PLC 都可以提供满足用户需要的解决方案。
易用性方面，PLC 作为取代继电器控制系统的控制器，在设计之初就充分考
虑了用户的使用体验。PLC 采用了图形化编程语言，降低了编程门槛，即便是没
有计算机编程背景的电气工程师，也能快速掌握 PLC 编程技术。同时，现代 PLC
还配备了功能完善的开发环境和调试工具，支持在线监控、断点调试等高级功能，
提升了开发效率和维护便利性，扩大了用户群体。
实时性方面，工业自动化系统对控制器的响应速度和时序精度有着严苛的要
求，而 PLC 采用专用的硬件架构、优化的实时操作系统、多任务调度机制和优
先级中断处理技术，使得其能够在微秒级别的时间内响应控制指令，保证关键控
制任务的及时响应。
可靠性方面，针对工业现场复杂多变的工作环境，PLC 采用了全方位的可靠
性设计。PLC 针对电气环境变化、温湿度环境变化,采用了专门的可靠性设计措
施，并在硬件结构上采用了工业级的设计标准，使其相较于硬件设计相对简单的
控制器具有更好的可靠性。
基于以上技术优势，PLC 在工业控制领域长期占据核心主导地位，应用领域
覆盖简单的单机设备控制到复杂的流程工业控制系统，成为工业自动化不可或缺
的关键设备。
（3）工业领域的新技术持续为 PLC 提供新的发展动能，进一步巩固其在工
业控制领域的核心竞争优势
自 1969 年 PLC 首次问世以来，其作为工业自动化领域的核心设备已经走过
了半个多世纪的技术演进历程，PLC 从最初简单的继电器替代装置，到具备复杂

运算能力的自动化控制器，再到如今成为集运动控制、网络通信、信息安全和人
工智能等多项工业技术于一体的复杂控制系统。
随着工业领域新技术的持续发展，5G、时间敏感网络（TSN）和开放平台通
信统一架构（OPC UA）等先进通信技术的集成应用，显著提升了 PLC 系统的通
信实时性、传输可靠性和系统开放性；人工智能算法等智能化技术的场景化落地，
进一步增强了 PLC 产品在复杂工业环境中的自适应能力和泛化性能。
在工业技术持续迭代的背景下，PLC 仍然呈现较强的技术包容性和产品生命
力。新兴技术并未催生替代性产品，而是通过持续赋能 PLC 实现功能升级与性
能优化，不仅拓展了 PLC 在工业控制领域的应用边界，更巩固了其在现代工业
自动化系统中的核心地位，使得 PLC 的技术内涵和应用边界也在不断拓展，充
分体现了 PLC 产品在工业控制领域的核心竞争优势。

（一）PLC 产品为标品还是定制化产品，以独立产品还是模块形式向客户销
售，模块主要搭配形式和销售占比，与客户二次开发和整套自动化设备的关系
1、PLC 产品是标准化的通用产品，以模块组合的形式向客户销售，模块主
要搭配形式和销售占比的具体情况
PLC 产品是标准化的通用产品，产品需符合 IEC 61131 系列国际标准以及
GB/T 15969 系列国家标准。在产品形态上，小型 PLC 主要采用整体式架构设计，
同时也可扩展少量外围模块，主要以独立产品形式进行销售；中大型 PLC 采用
模块式架构设计，具体的模块种类包括 CPU 模块、I/O 模块、通讯模块、功能模
块、电源模块、背板模块等不同种类的模块及附件，采用标准化的接口和电气规
范，根据用户的具体需求确定具体的模块搭配组合，以模块组合的形式向客户销
售。
在销售模式上，PLC 厂商提供标准化的模块型谱目录，客户可根据具体控制
需求自选相应的功能模块进行灵活采购，实现从简单逻辑控制到复杂过程控制等

不同层次的功能。
在搭配形式和销售占比上，中大型 PLC 构成的控制系统通常由 CPU 模块、
I/O 模块、通讯模块、电源模块等模块组合而成，在数量配比上视具体的控制需
求确定，不存在固定的配比关系，但存在大致的数量配比关系，具体请参见本题
回复之“一/（二）/2/（2）中型 PLC 与大型 PLC 的技术特性、市场应用领域对
比”。
2、PLC 产品与客户二次开发和整套自动化设备的关系
在工业自动化系统中，PLC 是核心控制中枢，通过与各类现场设备的系统集
成，构建以整套自动化设备为代表的自动化控制解决方案。该集成过程涵盖硬件
架构设计、通信协议配置、控制逻辑编程及系统联调等关键环节，通常由用户自
行完成，即用户基于标准化的 PLC 产品进行控制系统的“二次开发”形成“整
套自动化设备”。
具体实施过程中，用户需根据PLC制造商提供的技术规格文档及选型手册，
结合具体应用场景的I/O点数、控制规模、实时性要求及功能复杂度等关键要素，
确定需要采购的 PLC 产品及扩展模块的配置。在完成 PLC 硬件的物理安装后，
用户需进行现场总线网络的拓扑构建及通信参数配置，确保 PLC 与其他工控设
备间的数据交互畅通。完成以上步骤后，用户需要在符合 IEC 61131-3 标准的 IDE
中完成用户程序的开发，以让 PLC 实现具体的控制逻辑，包括工艺流程的时序
控制设计、运动控制参数设定以及安全联锁逻辑实现等核心功能。在系统的控制
需求发生变更后，用户需要结合实际情况调整硬件配置，例如增减 I/O 模块、替
换支持不同通信协议的通信模块等，调整 PLC 硬件后用户还需要在 IDE 中修改
程序调整控制逻辑以适应新的应用需求。
在此过程中，PLC 制造商主要提供标准化的 PLC 硬件平台及符合 IEC 
61131-3 标准的 IDE，而具体的用户程序开发及系统调试工作则由用户独立完成。
PLC 制造商提供的技术支持通常限于技术文档、技术支持热线，并不直接参与客
户端的系统集成过程的实施。

发行人的 PLC 生产过程主要包括半成品生产工序（即 PCBA 环节）和成品

序阶段，模块组装完成后需进行软件烧录和调试，将控制程序、通信协议等固件
写入硬件，并配合调试工具完成参数校准、功能验证及通信测试等工作，确保满
足工业环境的可靠性标准。
发行人生产过程的核心难点主要体现在高精度制造、高可靠性保障以及产能
与效率保障三个关键维度。在高精度制造方面，为确保发行人的 PLC 模块实现
先进的参数精度指标，需提升核心元器件的选型能力和校准工艺的先进水平。在
高可靠性保障方面，针对特定行业的严苛要求，发行人在生产流程中嵌入了包括
高低温循环试验、电磁兼容性测试、振动与冲击试验等多轮环境应力筛选，通过
加速应力环境来激发并剔除具有潜在早期失效风险的元器件。在产能与效率保障
方面，PLC 产品对 SMT 贴装精度、微焊接工艺及精密组装有较高要求，同时发
行人业务增长和多元化应用拓展对产能储备与制造体系的柔性提出了要求，必须
持续提升产线自动化水平和构建柔性制造能力，以满足敏捷制造的需求。
PLC 的生产过程涉及硬件装配、软件配置和系统调试的深度融合，需要协调
自动化、电子、信息技术等多个技术领域的专业知识实现高精度制造、高可靠性
保障以及产能与效率保障，具有较高的技术复杂度和工艺控制难度。
综上所述，外购元器件只是电子系统所需要的最基础的通用、成熟的元器件，
同时仅能作为发行人功能实现的载体，仅依靠元器件无法实现发行人产品的 PLC
可编程代码编译执行、现场总线与工业以太网通信、热备冗余等主要功能。发行
人的主要产品在形成过程中还需要发行人充分发挥研发设计环节的系统化产品
定义能力、软件及算法开发能力、硬件可靠性与结构化设计能力，生产环节的高
可靠性工艺技术，在此过程中并不单独依赖于某一环节或某一部分原材料。

（一）结合软硬件构成、应用场景需求等，说明 PLC 产品的技术难点、壁
垒所在
PLC 产品由硬件架构和软件系统构成。其中，硬件架构主要包括 PCB 组件、
处理器芯片、工业级壳体及接口电路等；软件系统主要包括 IDE（Integrated 
Development Environment，集成开发环境，用于逻辑编程、仿真调试及程序下载
的软件平台，需支持 IEC 61131-3 标准语言）和 Runtime（运行时，部署于 PLC
硬件中的实时执行引擎，负责扫描循环、任务调度及 I/O 控制，其性能直接决定
系统实时性）等。
PLC 产品的硬件架构决定了实时性、可靠性极限，而软件系统定义了 PLC
产品的核心功能。其中，IDE 是用户工程师进行 PLC 编程、配置和调试的核心
平台，部署在工程师的电脑上，实现项目管理、编程语言实现、硬件配置、仿真
与调试、编译与下载等功能；Runtime 是 PLC 的核心执行引擎，直接部署在 PLC
硬件之上，实现控制逻辑执行、任务调度、硬件交互、通信协议栈、系统服务、
安全功能等。就发行人而言，发行人完全自研了 IDE（集成开发环境）和 Runtime
（运行时），分别形成了“NAPro 多语言集成开发环境技术”和“针对不同架构
平台的嵌入式软件编译执行技术”两大成熟核心技术，为用户实现多语言二次编
程开发环境和高精度运行时环境。
基于 PLC 产品的软硬件构成，PLC 生产商如果想要基于自主技术生产出稳
定、成熟且具有市场竞争力的 PLC 产品，必须掌握以下四大核心技术能力：（1）
自主开发 IDE（集成开发环境）和 Runtime（运行时）的研发能力。（2）高可靠
性硬件设计制造能力，通过电路设计、结构设计实现产品的电磁兼容、温度湿度
等可靠性功能；适配主流处理器架构进行硬件平台开发的能力，包括对 X86 架
构、ARM 架构或国产的龙芯、飞腾等架构的硬件平台开发技术。（3）与主流工
业通信协议做好适配，掌握通信协议源码开发能力，实现支持 CANOpen、
PROFINET、EtherCAT、Modbus 等各类工业通信协议。（4）热备冗余、信息安

全等进阶功能的实现技术。具体如下：
1、PLC 产品作为工业领域的核心控制器，开发过程涉及多层次的软件技术
PLC 产品的核心功能主要由软件定义，软件算法是硬件效能发挥的关键枢纽，
产品开发过程需要研发团队掌握全方位的软件和算法技术，以满足现代工业自动
化系统对高性能、灵活性、可靠性和实时性的需求。
PLC 的软件系统构成要求研发团队掌握覆盖 IDE、Runtime 的全体系软件开
发能力。在 IDE 层面，需要构建符合 IEC 61131-3 标准的跨平台编译器与用户编
程界面，支持梯形图、结构化文本等多语言混合编程功能，确保用户程序被有效
地转换成可以在硬件上执行的指令；在 Runtime 层面，需要开发满足微秒级响应
要求的实时任务调度内核，通过任务调度算法和中断管理机制确保控制时序精度。
2、PLC 产品需要深入底层硬件，对硬件可靠性设计以及适配主流处理器架
构进行硬件平台开发的能力有较高要求
在硬件可靠性设计方面，现代工业自动化系统要求 PLC 产品在严苛环境下
保持长时间的稳定运行，因此 PLC 产品需要在硬件设计上实现电磁兼容性、环
境适应性等技术特点。
在电磁兼容性方面，需要开发具有电磁兼容特性的信号调理电路，在通道与
模块控制电路、内部总线通信电路、外部通信电路间，采用多重光电隔离、变压
器隔离等电气隔离和适合芯片特性的电气保护等措施，确保在强干扰环境下仍能
保持信号采集的精度。在环境适应性方面，需要采用专门的热力学设计，优化散
热结构，通过热仿真确定关键元器件的布局位置，通过防潮密封设计应对极端潮
湿环境。基于下游应用场景对 PLC 产品的硬件可靠性要求，PLC 产品的硬件设
计具备相当高的复杂度与技术难度。
在适配主流处理器架构进行硬件平台开发的能力方面，需具备针对不同处理
器架构的设计能力，以满足工业控制场景下高性能、高可靠性和长期稳定性的要
求。在具体实现上，PLC 产品需要支持 X86、ARM、MIPS、PowerPC 等主流架
构的指令集，并针对所选择的具体处理器架构特性进行深度优化。而对于采用国
产架构处理器开发 PLC 产品，研发团队还需要解决国产机构在外设缺失、开发
工具不完善、软件移植与适配等生态配套问题，需要投入更多精力解决兼容性与

生态问题。
3、PLC 产品需要具备与主流通信协议的适配功能，完善与其他层级工控设
备的兼容能力
PLC 产品需要实现与主流工业通信协议的高性能适配，研发团队需要建立完
整的通信协议栈自主适配开发能力，包括从物理层到应用层的全方位技术体系。
一方面需要在硬件层面针对不同总线协议的电气特性进行专门设计接口与电路，
另一方面在软件层面需要深入掌握各总线协议的通信机理，实现高效数据交互，
同时针对各种极端环境下的通信不稳定的特殊情况制定应对方案，例如在单一通
信链路中断时通过环网架构下的冗余通信方案保障整个系统的通信稳定性。内部
通信与外部通讯技术的实现要求研发团队既精通通信协议的底层实现细节，又具
备工业现场的实际部署经验，才能开发出既符合标准规范，又能满足严苛工业环
境要求的可靠通信功能。
4、中大型 PLC 产品需要具备冗余与信息安全等进阶功能，满足关键应用场
景的安全需求
热备冗余与信息安全等进阶功能是保障 PLC 产品连续可靠运行的技术，是
水利水电、石油石化、轨道交通等重要关键基础设施领域对于 PLC 产品的普遍
要求，其实现需要从硬件架构、软件算法到系统协同等多个层面进行综合设计。
在热备冗余方面，中大型 PLC 产品需构建完整的双机容错体系，通过硬件
上的冗余架构设计、软件上的数据同步算法，确保主备系统状态的一致性，实现
主控制器面临故障时无扰切换至备用控制器。PLC 研发团队需要深入多层次的硬
件与软件技术细节，提升 PLC 产品的热备冗余性能。
在信息安全方面，PLC 作为工业控制系统的关键控制器，是工业系统的安全
“红线”，一旦被入侵将产生严重的安全隐患。信息安全功能的实现一方面需要
PLC 产品基于特定的硬件技术实现可信启动等安全功能，另一方面在通信层面在
常规通信协议的基础上进一步实现数据加密功能、安全网关等功能。同时在网络
安全问题不断演变的背景下，研发团队还需与时俱进，持续掌握新兴的信息安全
技术并迭代进 PLC 产品中。
冗余与信息安全等进阶功能的实现，既需要研发团队掌握冗余架构设计、数

据同步算法、通信加密等底层技术，又需深入理解工业控制场景的具体需求，才
能构建出既满足高可用性要求，又符合工业安全标准的高可靠性 PLC 产品。
（二）中大型 PLC 产品较难开发的具体原因和受制因素
中大型 PLC 的难度在于应对系统性、多维度的复杂需求，而小型 PLC 则更
注重在有限资源下实现高性价比的可靠控制。两者差异本质上是应用场景的广度
与深度不同，中大型 PLC 面向复杂工业系统，需重视高性能与可靠性，而小型
PLC 则聚焦于单一设备的基础自动化，以简洁高效为核心目标。因此，中大型
PLC 产品的研发，必须从底层架构开始自主构建，实现 IDE 和 Runtime 的核心
技术突破，同时建立完善的硬件适配生态，此外，还必须通过长期严苛的现场验
证，才能最终获得客户认可；小型 PLC 通常可以依赖成熟的供应链，快速推出
产品。
小型 PLC 的技术难点，主要集中在紧凑型硬件设计、基础逻辑控制的高效
执行和成本控制方面。一方面，小型 PLC 需要在有限的机身空间内集成电路板、
处理器、存储单元和基本 I/O 接口，同时确保基本可靠性指标，对产品的结构设
计具有一定的要求；另一方面，小型 PLC 需要在资源相对受限的硬件平台上实
现执行周期确定的逻辑控制，因此需要对软硬件资源进行裁剪，通过适当精简不
需要使用的指令集和优化固件来最大程度利用有限的资源，保证基础控制功能的
实时响应。
与小型 PLC 不同，中大型 PLC 的技术难度主要体现在核心软件架构、硬件
深度开发、通信兼容适配以及冗余安全等进阶功能实现，需要构建更为复杂的多
层次技术体系，每一环节都面临技术挑战。具体分析如下：

•适配主流及国产处理器架构：针对不同架构特性进行深度优化，提升硬件平台性
能，解决国产架构的生态配套问题
通信兼容
适配
•多协议支持：需集成工业以太网（EtherCAT、PROFINET）、现场总线（Modbus、
CANopen）及 OPC UA 等协议栈，协议间的数据映射和同步复杂
•网络架构复杂：中大型 PLC 需要构建复杂的网络架构，实现设备之间的高效通信
和数据传输，需处理网络延迟、数据一致性及安全性（如加密认证）
•跨平台兼容性：不同厂商设备互联时，需适配协议转换或网关功能
冗余安全
等进阶功
能

现在单一设备出现故障时可在毫秒级周期内切换至另一台设备，确保实现生产过
程连续性
•热备冗余的同步精度会占用硬件平台的资源从而影响 PLC 的性能，做到 I/O 点位
级、控制任务级、控制指令级冗余难度递增

的额外要求，中大型 PLC 还存在着开发与维护成本高、生态兼容性与长期维护
等应用领域与市场生态带来的实际应用难题，具体如下：

开发与维
护成本

•认证标准：通过 CE、FCC、船级社等国际认证，需额外设计和测试投入。

维护

（一）结合下游客户选择 PLC 产品及供应商的主要考量因素，说明衡量各
类 PLC 产品优劣的关键性能指标
衡量中大型 PLC 与小型 PLC 的关键性能指标具体如下：
（1）软硬件规格
软硬件规格是决定 PLC 性能的基本指标，用户选择中大型 PLC 与小型 PLC
均需要考虑到指标。其主要包括内存与支持的编程语言两个具体的技术指标。内
存是 PLC 用于存储程序和数据的空间，数值越大，则 PLC 会具有更好的性能。
PLC 支持的编程语言是指可以用于编写 PLC 用户程序的语言种类，IEC61131-3
标准规定了 5 种标准的编程语言，支持的语言种类越多则用户使用 PLC 编写程
序的方式越灵活，同时支持 C/C++/Python 等高级编程语言的 PLC 可以支持用户
使用高级语言编写高级的算法程序。
（2）实时控制能力

工业自动化领域一般会要求控制系统能够做到实时控制，实时控制能力是用
户选择中大型 PLC 与小型 PLC 均需要考虑的指标，其主要通过位指令速度衡量，
位指令速度决定了 PLC 执行单条指令的用时，位指令速度数值越小，则 PLC 运
行速度越快，实时控制能力也越强。
（3）扩展能力
扩展能力是衡量 PLC 对设备接入的上限、I/O 信号类型的衡量指标，是用户
选择中大型 PLC 与小型 PLC 均需要考虑的指标，但由于二者面向场景不同，具
体的细分指标也有所不同。
中大型 PLC 面向的使用场景要求 PLC 具有足够大规模的扩展能力以支持大
I/O 点数接入，因此对于中大型 PLC 的扩展能力的衡量指标主要包括数字量与模
拟量的输入/输出、最大远程分站数量、扩展 I/O 模块最大数量等具体的技术指标，
数字量与模拟量输入/输出决定了 PLC 可以采集与控制的设备的规模，最大远程
分站数量决定了 PLC 可远程扩展的远程机架数量，扩展 I/O 模块最大数量决定
了 PLC 可扩展接入的 I/O 模块数量，数字量与模拟量的输入/输出、最大远程分
站、扩展 I/O 模块最大数量的数值越大，则 PLC 的扩展能力越强，越能胜任大
型自动化系统的控制。
小型 PLC 虽然控制规模较小，但仍需具备适度的扩展能力以适应不同应用
场景的需求。衡量小型 PLC 扩展能力的指标包括数字量与模拟量的输入/输出、
扩展 I/O 模块最大数量、高速输入/输出等具体指标，其中模拟量的输入/输出、
扩展 I/O 模块最大数量指标的含义与中大型 PLC 相同，高速输入/输出体现了小
型 PLC 对编码器、步进电机等高速信号的处理能力，是衡量小型 PLC 在步进电
机、简单伺服控制等场景下的控制能力的重要指标，由于小型 PLC 通常以整体
式架构为主，因此通常不涉及最大远程分站数量这一中大型 PLC 的特有指标。
（4）通信能力
在大型自动化系统中，PLC 需要和多种多样的现场设备互连互通，同时不同
下游行业和不同的设备可能使用不同的通信协议。因此 PLC 的通信能力成为了
衡量 PLC 与工业现场其他设备之间的组网能力与兼容性的重要指标，该指标是
用户选择中大型 PLC 与小型 PLC 均需要考虑的指标。

通信能力包括通信接口（有线通信接口、无线通信接口）、支持的通信协议
两个具体技术指标。PLC 常用的通信接口包括以太网接口和串口接口，更多的通
信接口和多样的接口类型使得 PLC 可以同时连接多个设备并支持更丰富的网络
拓扑结构，更能适应不同使用场景的通信需求。支持的通信协议是 PLC 与其他
设备之间进行数据交换和通信的规则和约定，支持的通信协议类型越多，则 PLC
对其他设备之间的组网能力与兼容性越强。
（5）热备冗余能力
PLC 的热备冗余能力是指 PLC 系统在发生故障时能够无缝切换到备用 PLC
并保持对工业过程的连续控制的能力。在大型工业自动控制系统中，任何停机或
中断都可能导致严重的生产损失或安全风险，因此热备冗余能力是衡量 PLC 稳
定性的重要指标。该指标主要是用户选择中大型 PLC 时需要考虑的指标，小型
PLC 的使用场景通常会定期进行系统停机，不要求 PLC 具备热备冗余功能，因
此通常不考虑该指标。
热备冗余能力具体技术指标包括冗余模块类型。冗余模块类型是指 PLC 的
模块中支持冗余功能的模块种类，支持冗余的模块种类越多，则 PLC 的冗余能
力越完备。
（6）电磁兼容性
PLC 的电磁兼容性指的是 PLC 设备在电磁环境中与其他电子设备共存和正
常运行的能力。中大型的 PLC 所面向的能源、电力等工业场景的电磁环境较为
复杂，要求 PLC 具备较强的抗电磁干扰能力，因此电磁兼容性是衡量中大型 PLC
稳定性和可靠性的重要指标，小型PLC的应用场景主要为环境良好的生产车间，
对 PLC 的电磁兼容性通常没有特殊要求，因此用户选择小型 PLC 时通常不考虑
该指标。
常用的电磁兼容性指标主要包括浪涌抗扰度、快速瞬变、静电放电三个具体
技术指标，浪涌抗扰度是指 PLC 对瞬时电压浪涌干扰下的抵抗能力、快速瞬变
是指 PLC 设备对高速电压瞬时变化干扰的抵抗能力、静电放电是指 PLC 与带电
物体接触时对由于静电的积累和释放而产生的瞬态电流脉冲的抵抗能力。
IEC61000-4 国际标准针对 PLC 的以上电磁兼容性指标制定了分级标准，数值越

大、等级越高则代表 PLC 的电磁兼容性越好，越能胜任电磁环境复杂的使用场
景。
（7）环境适应性
PLC 的环境适应性指的是 PLC 在极端环境条件下的适应能力，中大型 PLC
所面向的使用场景要求 PLC 能在各种严苛的工业环境条件下长期稳定运行，因
此环境适应性是衡量中大型 PLC 可靠性的重要指标，小型 PLC 的应用场景主要
为环境良好的生产车间，对 PLC 的环境适应性通常没有特殊要求，因此用户选
择小型 PLC 时通常不考虑该指标。
环境适应性主要包括工作温度与工作湿度两个具体的技术指标。工作温度与
工作湿度的范围越宽则 PLC 对极端温度与湿度的适应能力越强。
（8）运动控制能力
小型 PLC 主要用于设备自动化领域，主要用于对伺服系统等驱动、执行层
设备的控制，需要支持一定的运动控制功能完成对设备的控制，而中大型 PLC
的应用领域以系统自动化领域为主，伺服控制非主要应用场景，因此用户主要在
选择小型 PLC 时会考虑该指标。衡量小型 PLC 的运动控制能力的指标包括运动
控制轴数、支持的运动控制算法两个具体指标。运动控制轴数越多，则小型 PLC
对伺服或步进电机等设备的插补精度越高，运动控制路径规划越精确。运动控制
算法主要衡量小型 PLC 对电子凸轮等特殊算法等支持程度，支持的运动控制算
法越多则小型 PLC 的应用场景越广泛。
（二）区分不同应用领域和小、中、大型 PLC 产品，充分对比发行人产品
与国内外竞争对手主流产品、先进产品的关键性能指标和实际应用效果
PLC 是一种通用控制器，不同应用领域对于 PLC 产品的差异化需求主要通
过以下两种方式满足：一是扩展各类特殊功能模块，例如电力行业的事件记录需
求由 SOE 模块实现、运动控制领域的高速计数需求通过高速计数模块实现；二
是依托软件算法功能，例如过程控制领域的温度、压力控制需求通过 PID 软件算
法实现、运动控制领域的运动控制需求通过专门的运动控制算法实现。基于特殊
功能模块扩展和软件算法功能升级两种方式，不同应用领域的技术特性可以集成
进同一系列 PLC 产品，因此在对比 PLC 产品的关键性能指标时无需区分不同应

用领域采取差异化的对比维度。
1、中大型 PLC 产品关键性能指标
中大型 PLC 采用模块式架构设计，同一系列产品包括 CPU 模块、通信模块、
I/O 模块、电源模块、背板模块及特殊功能模块。中大型 PLC 产品的 I/O 模块、
通信模块等外围模块主要起到供电、连接、通信、设备接入等功能，而 PLC 的
最大 I/O 点数、指令执行速度等关键性能指标均由 CPU 模块决定，因此在产品
性能对比层面，用户主要关注 CPU 模块的性能。
综上，发行人在行业内主要国际品牌与国产品牌的官方网站或技术文档中公
示的中大型 PLC 产品系列的 CPU 模块中，选取了部分主流、先进规格型号产品，

游客户使用较多的系列产品，选取的先进规格型号为各品牌参数指标靠前、支持
冗余等进阶功能的高端系列产品。

2、NAPro 软件平台的技术难度
IDE（集成开发环境软件）是用于编写、调试和下载 PLC 程序的软件平台，
需要支持多种编程语言，且与硬件模块、通信协议深度集成，且必须搭配自研配
套的嵌入式软件 Runtime（运行时），方可确保 PLC 程序的正确执行。
集成开发环境软件的开发，需要深厚的软件工程能力，特别是多编程语言与
图形化设计、编译器开发与实时性优化、硬件驱动开发与协议栈实现、调试与仿

真工具集成等各方面。国内很多 PLC 企业早期更加重视硬件制造，在软件研发
尤其是在底层编译器和 Runtime（运行时）软件开发方面相对缺乏足够的经验。
发行人的 NAPro 软件平台作为 PLC 的集成开发环境软件有突出表现，主要
体现在核心功能复杂、硬件兼容性挑战、调试与诊断工具开发、行业标准适配、
用户体验与跨平台生态支持等方面。此外，NAPro 在兼容性、扩展性、安全性等
方面也有独特的设计。具体如下：
（1）核心功能复杂，支持多编程语言，掌握优秀的编译技术和实时性优化
能力
集成开发环境软件的核心功能开发复杂度高，具体体现在编程语言支持、编
译与验证、实时性要求方面。
1）编程语言支持：集成开发环境软件需要支持包括梯形图 LD、指令表 IL、
结构化文本 ST、功能块图 FBD 和顺序功能图 SFC 等多种编程语言，每种编程
语言的编辑器、编译器和调试器都需要开发者单独设计实现，使得开发复杂度较
高。NAPro 软件平台支持 IEC 61131-3 全系语言，允许 LD、ST、FBD 混合编程，
且内置多个行业模板库，减少用户开发时间。
2）编译与验证技术，及实时性优化：将高级语言代码转换为 PLC 可执行的
机器码，需兼顾效率与实时性。例如，复杂算法（如 PID 控制）的代码优化需避
免扫描周期波动。在用户程序编译环节，集成开发环境软件既要实现高效的目标
代码转换，又要确保包括地址越界、循环依赖等实时语法检查和逻辑验证，对开
发者的技术能力要求较高。工业场景对代码执行确定性的严苛要求，需要通过多
种方式优化编译算法，对开发者的技术储备要求较高。NAPro 搭载自研编译器，
支持龙芯、飞腾等国产芯片，提高生成代码效率。
（2）生态兼容性问题，需配合硬件平台、操作系统、通信协议进行持续升
级迭代
集成开发环境软件的硬件兼容性要求带来额外挑战，具体体现在协议与驱动
集成、硬件仿真方面。
1）跨平台支持：用户运行集成开发环境软件的上位机平台可能采用 Windows、
Linux 乃至麒麟国产操作系统等多类平台，需要在软件开发过程考虑跨平台框架。

2）协议与驱动集成：由于工业自动化领域的其他设备采用如 Profibus、
EtherCAT 等专有通信协议，集成开发环境软件需要集成多种通信协议的协议驱
动和调试接口，而相关通信协议大多只公开了标准规范但未公开实现方式，要求
开发者自行完成，多种通信协议的开发造成了明显的技术难度。
（3）仿真、调试与诊断工具开发难度
1）硬件仿真：PLC 用户需要模仿实际应用场景对 PLC 进行调试，要求集成
开发环境软件具备离线仿真功能，离线仿真功能的实现需要开发者对 PLC 硬件
行为进行精确建模，提升了技术门槛。NAPro 支持虚拟仿真，模拟极端工况。
2）实时监控功能：集成开发环境软件需要提供完善的实时监控功能，包括
变量监视、测点强制、断点调试和时序分析等功能，要求集成开发环境软件与
PLC 嵌入式软件 Runtime（运行时）能做到保持高效通信；
3）故障诊断功能：需要深度解析 PLC 状态数据，实现硬件诊断和程序逻辑
分析。NAPro 集成故障诊断功能，工程师可快速定位故障。
（4）用户体验与生态门槛
集成开发环境软件作为用户进行 PLC 程序开发的平台，做到优秀的用户体
验与兼容不同平台的上位机操作系统同样存在技术门槛。集成开发环境软件的工
程管理功能需要做到支持大型项目，实现多设备协同、程序版本控制，同时支持
用户自定义功能块的库管理功能。

（三）说明多数同行业企业未自行开发平台软件的原因、合理性
根据同行业企业网站公开的技术文档等资料，发行人同行业企业中，如西门
子、罗克韦尔、施耐德等国外企业均自行研发 PLC 的集成开发环境软件，主要
由于相关企业较早进入了 PLC 领域，构建了完整的软件技术体系。国内多数同
行业企业，未在主打产品中自行开发平台软件，主要是由于政策导向、技术门槛
和用户生态三大因素所致。
其一，我国 PLC 行业早期缺乏明确的自主可控政策要求，因此国内厂商普
遍采用国外成熟的软硬件解决方案。同时，汇川技术、信捷电气、禾川科技等企
业的产品以小型 PLC 为主，小型 PLC 的下游客户多为纺织机械等设备自动化领
域的民营制造业客户，这类客户更注重产品性价比而非产品技术的自主可控；发
行人的产品以中大型 PLC 为主，客户多为关键基础设施领域的国有企业，对供
应链安全有一定倾向，因此在客户需求的推动下更早开展自主集成开发环境软件
平台的研发工作。

其二，集成开发环境软件作为 PLC 的程序开发平台，其在核心功能复杂、
硬件兼容性挑战、调试与诊断工具开发、行业标准适配、用户体验与跨平台生态
支持等方面均存在一定的技术难度，使得自行开发该软件需要较高的研发投入以
及后续软件维护的成本，提高了自行开发该软件的门槛。直接采用 CodeSys 成熟
套件可以显著减小产品开发成本，降低自主研发失败的风险，因此多数企业未自
行研发软件具有合理性。
其三，CodeSys 平台经过长时间的行业推广，已在 PLC 领域特别是主打运
动控制的小型 PLC 领域构建了一定的用户生态。对于同样采用 CodeSys 平台的
PLC 产品，用户的使用体验相对一致，也减小了用户切换品牌的隐性成本。因此，
国内企业选择融入 CodeSys 生态可以更快的打开市场渠道，具备商业合理性。

（一）核查依据、过程
1、查阅 PLC 相关国际标准、国家标准、市场报告、行业内上市公司公开披
露的文件，了解行业内对于 PLC 产品划分的依据；
2、取得各类型 PLC 产品应用典型工业自动化系统的报价清单，查阅 PLC

度和价值量占比、与其他工业自动化设备的适配情况、是否存在替代性产品，与
下游客户访谈了解产品使用寿命、更新迭代频率或采购周期；
3、与发行人了解 PLC 产品的销售形式、模块搭配形式、产品核心零部件情
况与核心技术具体体现情况、开发难度与定价策略；
4、查阅 RTU 相关研究报告，查阅同行业公司 RTU 产品的产品参数明细，
了解 RTU 产品的技术难度；
5、查阅 PLC 行业相关论文、查阅同行业公司 PLC 产品的产品参数明细，
与发行人了解 PLC 产品的技术难度、发行人核心技术体现、衡量 PLC 产品性能
的关键指标、发行人与竞争对手的对比情况、发行人 NAPro 软件平台的开发过
程和技术难度、与 CodeSys 的对比情况；

（二）核查意见
经核查，保荐人认为：
1、发行人基于 I/O 点数划分 PLC 产品的口径符合行业惯例，具有合理性；
小型 PLC 用于单机控制，技术难度低；中大型 PLC 适用于复杂系统，技术难度
高。PLC 与驱动层、执行层设备适配性强，通过标准化接口和协议实现兼容。
PLC 寿命通常在 10-15 年，技术迭代更新周期 7-10 年，替代产品技术局限性强，
目前 PLC 凭借通用性、可靠性等优势占据市场核心地位，被替代的风险较小；
2、PLC 为标品，中大型 PLC 通常以模块组合形式销售，小型 PLC 通常以
独立产品销售；PLC 模块搭配灵活，无固定比例，客户根据实际需求选择配置；
发行人的 CPU PCBA 板等核心部件均为外购原材料后通过自主工艺生产，核心
技术体现在研发设计、软硬件开发及生产等环节；
3、发行人已在招股说明书中补充披露远程测控终端（RTU）产品的技术难
度和先进性，与同行业可比公司类似产品关键性能指标的对比情况；
4、PLC 开发涉及多学科交叉，技术复杂度高，需解决实时性、通信协议、
可靠性等难题；中大型 PLC 因模块化设计、冗余技术等要求更高，开发难度显
著大于小型 PLC；发行人形成了六大核心技术集群，核心技术的先进性具体体现
在硬件体系和热备冗余技术、软件体系、通信与网络集成、功能与性能以及行业
专用技术积累等层面；
5、发行人的中大型 PLC 在整体性能指标上与竞品达到同一水平，并在支持
的编程语言种类、扩展 I/O 模块最大数量、支持的通信协议、热备冗余能力、电
磁兼容性、环境适应性等指标上更具备优势；发行人的小型 PLC 整体性能指标
与同行业主流产品持平，并在程序空间、实时控制和扩展能力等指标上具备竞争
优势。
